# 👶 베이비빌리(BabyBilly) 백엔드 개발자 채용 과제

안녕하세요! 베이비빌리 백엔드 개발자 채용 과정에 지원해 주셔서 진심으로 감사합니다. 🙌

본 과제는 **실무 중심 과제**로, 지원자분이 실제 베이비빌리 서비스 환경에서 마주할 법한 문제를 어떻게 정의하고, 설계하고, 해결하는지를 보고자 합니다.

> 🤖 **AI 도구 활용을 적극 권장합니다.**
> Claude, ChatGPT, Cursor, GitHub Copilot 등 어떤 AI 도구든 자유롭게 사용하세요.
> 저희가 궁금한 것은 "AI 없이 짤 수 있는가"가 아니라, **"AI를 어떻게 지휘하고, AI가 만든 결과물의 한계를 어떻게 발견·보완하는가"** 입니다.

---

## 1. 기술 스택 및 인프라 환경

| 구분 | 내용 |
| --- | --- |
| **Backend** | Node.js, TypeScript, **NestJS (권장)** |
| **Database** | MySQL 8.0 (Aurora MySQL 호환) |
| **Cache / Lock** | Redis 7 |
| **Message Broker** | RabbitMQ 3 |
| **로컬 인프라** | 제공된 [`docker-compose.yml`](./docker-compose.yml) 활용 |

### Production Context (가정)

구현물은 다음과 같은 운영 환경에서 동작한다고 **가정**하고 설계해 주세요.

- **AWS EKS** 기반의 **마이크로서비스 아키텍처(MSA)**
- 서비스 간 결합도를 낮추는 **이벤트 기반 아키텍처(Event-Driven Architecture)**
- 다수의 Pod가 수평 확장(Horizontal Scaling)되어 동시에 요청을 처리하는 환경

> 실제로 EKS에 배포할 필요는 없습니다. 다만 "인스턴스가 여러 대일 때도 이 로직이 안전한가?"를 염두에 두고 설계해 주세요.

### 로컬 인프라 실행

```bash
docker compose up -d
docker compose ps   # 모든 서비스가 (healthy) 상태인지 확인
```

| 서비스 | 접속 정보 |
| --- | --- |
| MySQL | `localhost:3306` / DB: `babybilly_test` / user: `babybilly` / pw: `babybilly` (root pw: `root`) |
| Redis | `localhost:6379` |
| RabbitMQ | AMQP `localhost:5672` / 관리 콘솔 http://localhost:15672 (`guest` / `guest`) |

## 2. 과제 미션 🎯

### 베이비빌리 서비스 소개

베이비빌리는 임신·육아 가정을 위한 앱으로, 다음과 같은 기능을 제공합니다.

- 📅 **임신·육아 시기별 맞춤 정보** — 임신 주차 / 아이 개월 수에 맞춘 콘텐츠 제공
- 👩‍👩‍👧 **동기 커뮤니티 '베동'** — 같은 시기에 출산·육아하는 부모들의 커뮤니티
- 🛒 **커머스** — 임신·육아 용품 판매
- 🔔 **대량 푸시 알림** — 시기별 정보, 이벤트, 커뮤니티 활동 알림

### 미션

> **베이비빌리 앱에 추가되면 좋을 기능 1가지를 직접 기획·상상하여, 백엔드 API와 DB 스키마를 구현해 주세요.**

### ⚠️ 필수 조건

단순 CRUD 구현에서 그치지 않고, 해당 기능에서 발생할 수 있는 **핵심 기술적 병목**을 아래 중 **1가지 이상** 선택해 이를 해결하는 **아키텍처와 방어 로직을 반드시 포함**해야 합니다.

| 병목 유형 | 예시 상황 |
| --- | --- |
| **대규모 트래픽 동시성 제어** | 선착순 이벤트, 한정 수량 상품, 중복 참여 방지 |
| **데이터 정합성** | 재고·포인트 차감, 분산 환경의 트랜잭션, 멱등성 보장 |
| **비동기 큐 처리** | 대량 푸시 발송, 이벤트 발행/구독, 재시도·DLQ 처리 |
| **외부 장애 대응** | 외부 API 타임아웃, 서킷 브레이커, Fallback, 보상 트랜잭션 |

### 평가 포인트

- 기능 기획의 **도메인 이해도**와 문제 정의의 명확성
- 선택한 병목에 대한 **해결 전략의 타당성**과 **트레이드오프 인식**
- 코드 품질, 구조, 테스트 가능성
- **AI 활용 역량** — 프롬프트 설계, AI 결과물 검증 및 개선 능력
- **작업 과정의 투명성** — 커밋 히스토리와 AI 리포트

## 3. Git 작업 및 AI 기록 규칙 ⭐ (중요)

1. **Private 저장소에서 시작하기**
   - 본 템플릿을 복사해 지원자 본인의 **GitHub Private 저장소**를 생성해 주세요.
   - **첫 커밋(Initial Commit)을 먼저 푸시한 시점부터 작업을 시작**해 주세요.

2. **기능 단위로 자주, 의미 있는 커밋하기**
   - 작업 과정과 의사결정 흐름이 드러나도록 **기능 단위로 자주 커밋**해 주세요.
   - 모든 코드를 한 번에 통째로 올리는 **Big Bang Commit은 지양**해 주세요.
   - 커밋 메시지 컨벤션(예: Conventional Commits)은 자유이나, 일관성 있게 작성해 주세요.

3. **`AI_REPORT.md` 작성하기**
   - 동봉된 [`AI_REPORT.md`](./AI_REPORT.md) 양식에 다음 내용을 성실히 작성해 주세요.
     - 핵심 프롬프트
     - AI 코드의 한계를 발견해 직접 수정한 사례
     - 관련 커밋 해시 (7자리)
     - 웹 AI 대화 공유 링크 (해당 시)

> 📌 **제출된 프롬프트와 커밋 타임라인은 2차 기술 면접에서 상세 질의의 기준으로 활용됩니다.**
> 본인이 직접 이해하고 설명할 수 있는 수준으로 작업해 주세요.

## 4. 제출 방법 📮

1. 아래 항목을 모두 **커밋·푸시**해 주세요.
   - `README.md` — 본 안내문 하단(또는 별도 섹션)에 다음 내용을 추가

   - **`AI_REPORT.md`**
